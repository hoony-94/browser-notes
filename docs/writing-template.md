# [기능 이름보다, 내가 풀고 싶은 질문]

아래는 글을 구상하는 질문 목록이다. 실제 파일은 `docs/note-template.mdx`를 `src/content/notes/<slug>.mdx`로 복사해 시작한다. 작성 규칙은 [authoring.md](authoring.md)를 참고한다.

- 주제: 로딩과 네트워크 / 렌더링과 인터랙션 / 웹의 경계
- 상태: 질문 / 실험 설계 / 정리됨
- 시작일 / 마지막 확인일:
- 태그:
- 실제 검증 환경: 브라우저, OS, 런타임, 프레임워크 버전, CDN

## 1. 왜 이 질문인가

직접 겪은 현상이나 기존 설명에서 납득되지 않은 부분. 내 최초 가설과 예상.

## 2. 기능이 해결하려던 문제

이전 방식의 제약, 표준·설계 문서의 근거. 설계자의 의도와 나의 해석을 분리한다.

## 3. 비교와 실험

- 비교군 / 바꾸는 조건 / 통제할 조건:
- 재현 명령, 데모 또는 코드:
- 시뮬레이션인지 실제 측정인지:
- 원본 로그·트레이스·화면과 반복 측정 결과:
- 실패한 조건과 반례:

## 4. 프레임워크라는 사례

브라우저 기본 동작 → 런타임 → 프레임워크 → 배포 플랫폼을 구분한다. 어디에서 어떤 정보와 제어권이 생기는가? 도구가 보장하는 것과 환경에 의존하는 것은 무엇인가?

## 5. 내가 내린 판단

관찰한 사실 / 해석 / 추정 / 미해결을 분리한다. 무엇 때문에 판단이 바뀌었는지, 어떤 조건에서 이 기능을 쓰지 않을지 적는다.

## 6. 브라우저에 바라는 것

해결하고 싶은 문제, 최소 API 스케치, 기존 방식과의 비교, 접근성·개인정보·자원 비용·하위 호환성의 대가. 제안은 현재 제공되는 기능과 명확히 구분한다.

## 7. AI와 함께한 범위

AI가 만든 코드·설명 / 직접 읽은 출처 / 사람이 수행한 검증 / 아직 검증하지 못한 부분.

## 8. 근거와 수정 기록

원문 링크, 근거가 되는 절·코드 위치, 확인 날짜. 이후 결과가 바뀌면 이유와 수정 날짜를 추가한다.
